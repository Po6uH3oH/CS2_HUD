# CS2 Broadcast Control

Для продолжения разработки в новом чате: [актуальное состояние и карта проекта](docs/current-state.md). Настройка полоски карт: [карты серии и счётчик игроков](docs/hud-series.md).

Локальная система оформления трансляции CS2 для Windows: игровой HUD, экран пауз, панель оператора, предпросмотр, GSI, FACEIT и управление OBS. Интерфейс основан на предоставленных GAME.png и TIMEOUT.png. Основное полотно — 2560 × 1440, пропорциональное масштабирование до 1920 × 1080.

**Статус: рабочая версия после первого live-матча.** Исправления проверяются автоматическими тестами и в браузере; новые изменения ещё нужно проверить в следующем эфире. Интеграция с приватным FACEIT Hub требует отдельной проверки. Встроены десять радаров с overview-параметрами CS2, включая два этажа Nuke. Сверьте совпадение точек на своей версии игры.

## Скачать и запустить

**[Скачать готовое приложение для Windows x64](https://github.com/Po6uH3oH/CS2_HUD/releases/latest)** → в Assets выберите **CS2-HUD-0.2.0-win-x64.zip**.

1. Распакуйте ZIP целиком через «Извлечь всё».
2. Запустите **CS2 HUD.exe**. Node.js, Electron, база SQLite и все зависимости включены. Терминал и права администратора не нужны.
3. Настройте GSI по [инструкции первого запуска](docs/first-run.md). Без подключения игры HUD ожидает данные; для просмотра оформления включите «Демо».

Для OBS без внешнего окна запускайте **START_OBS.bat** из готового архива. Для окна поверх CS2 используйте видеорежим без рамки. [Управление окном и горячие клавиши](docs/desktop-overlay.md).

Готовое приложение хранит настройки в `%LOCALAPPDATA%\CS2HUD`, отдельно от папки новой версии. Выйдите через **Завершить HUD**, распакуйте обновление и запустите его. Собственные замены иконок из `resources/app/assets/icons` перенесите отдельно. Исходники по-прежнему используют `data` рядом с проектом. Порядок переноса базы и журналов описан в инструкции.

**Code → Download ZIP** скачивает исходники. После распаковки нажмите **START_OVERLAY.bat** или **START.bat**: первый запуск автоматически загрузит локальный Node.js, проверит/установит зависимости и соберёт интерфейс. Требуется Интернет только для подготовки; при ошибке окно останется открытым, журнал — `data/setup.log`. Наличие папки node_modules больше не считается успешной установкой.

Кнопки пауз управляют графикой и не ставят на паузу сервер FACEIT. Ручная пауза действует до «Вернуть игру». Сервер стартует в LIVE; Demo включается явно, после возврата в LIVE искусственные данные очищаются.

## Быстрая подготовка матча

В «Командах» T показана слева, CT справа; после смены сторон расположение меняется вместе с GSI. В «Библиотеке» уже есть 10 сохранённых команд из комплекта `assets/library/teams.json`. Они добавляются один раз, без перезаписи существующих записей.

Перед новой серией в «Матче» нажмите **Новый матч**, выберите BO, команды и порядок карт кнопками, затем сохраните изменения. Текущая карта автоматически берётся из GSI. При подтверждённом `gameover` победителю добавляется карта серии — даже если её не было в списке. Повторные пакеты и перезапуск сервера не добавят её второй раз. Для уже сыгранных до подключения HUD карт задайте счёт вручную. Если подключились на экране окончания карты, её результат также будет учтён; проверьте ручной счёт, чтобы не включить эту карту дважды. Повтор одной карты в той же серии автоматически не засчитывается повторно: для переигровки поправьте счёт вручную.

## Команды после ножевого раунда и замены

В «Матче» или «Командах» откройте **Кто за какую сторону**, проверьте никнеймы, при необходимости нажмите **Поменять стороны**, затем **Привязать текущих игроков → Сохранить изменения**. Одного известного игрока достаточно для автоматического определения всей стороны, включая замены. Для ручного управления выключите автоопределение; сохранение применяется сразу, без перезапуска HUD. [Инструкция по составам, смене сторон и loss-бонусу](docs/team-assignment.md).

## Название Twitch

В **Настройки → Подключения → Twitch** задайте шаблон с переменными команд и счёта, подключите канал и включите автообновление. [Пошаговая инструкция и список переменных](docs/twitch-title.md).

## Разработка и сборка релиза

Обычным пользователям достаточно готового ZIP или BAT выше. Для разработки используются Node.js 24+ и pnpm 11.25.0, закреплённые в проекте:

```powershell
npm install -g pnpm@11.25.0
pnpm install --frozen-lockfile
pnpm build
pnpm start
```

Без глобальных инструментов выполните `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/bootstrap.ps1 -Mode setup`. Локальные инструменты будут в `.runtime`; системные установки не изменяются. [Сборка и публикация готового ZIP](docs/releases.md).

Для разработки:

```powershell
pnpm dev
```

Backend: `http://127.0.0.1:3190`; Vite: `http://127.0.0.1:5173`. Vite проксирует API и WebSocket. Для эфира используйте собранную версию на 3190: она не зависит от dev-сервера.

Проверки:

```powershell
pnpm typecheck
pnpm test
pnpm build
```

Интеграционным тестам требуется доступ к localhost. Тесты используют временную SQLite, тестовые токены, подменённый FACEIT HTTP и локальный сервер протокола OBS; реальный эфир они не переключают.

## Подключение CS2

1. В панели откройте **Настройки → Подключения → Скачать .cfg**. Сервер подставляет свой порт и отдельный случайный GSI-токен.
2. В Steam откройте CS2 → Управление → Просмотреть локальные файлы.
3. Поместите `gamestate_integration_broadcast.cfg` в `game/csgo/cfg` внутри каталога игры.
4. Если конфиг уже был установлен, замените старый файл новым: теперь `buffer=0`, `throttle=0.05` (до 20 обновлений в секунду при наличии изменений). Полностью перезапустите CS2. Подключитесь разрешённым наблюдателем / к разрешённой трансляции или локальной демозаписи.
5. В панели выберите «Матч» вместо «Демо» и откройте «Настройки → Диагностика»: должны поступать пакеты и появиться список доступных данных. Для состава из 10 игроков и позиций нужен spectator-набор GSI; режим обычного игрока его не заменяет.

Не распространяйте сгенерированный cfg с токеном. Пример без секрета лежит в `config/gamestate_integration_broadcast.example.cfg` и требует замены токена. Предпочтителен файл, скачанный из панели.

Проект использует только HTTP GSI и разрешённые внешние API. Он не читает память игры, не внедряется в CS2 и не взаимодействует с FACEIT Anti-Cheat. Прозрачное окно Electron отображает тот же HUD поверх рабочего стола, пропускает мышь в игру и не внедряется в процесс CS2. Для него нужен оконный режим без рамки; эксклюзивный полноэкранный режим не поддерживается.

## OBS

Добавьте Browser Source поверх захвата игры:

| Назначение | Адрес |
|---|---|
| Единый источник с автоматическим переключением | `http://127.0.0.1:3190/overlay/production` |
| Только игровой HUD | `http://127.0.0.1:3190/overlay/game` |
| Только экран паузы | `http://127.0.0.1:3190/overlay/pause` |

Для единой сцены выберите `/overlay/production`. Он слушает ручную видимость и автоматически показывает паузу по активному состоянию. Для нескольких сцен добавьте `/overlay/game` и `/overlay/pause` в соответствующие сцены: эти адреса всегда показывают заданный тип оверлея, независимо от выбора production.

Размер Browser Source: **2560 × 1440**, частота 60 FPS. Фон полностью прозрачный на всех `/overlay/*` и `/preview`, в том числе на паузе; полос прокрутки и интерфейса администратора нет. На холсте OBS 1920 × 1080 источник можно уменьшить пропорционально либо задать ему 1920 × 1080 — композиция автоматически масштабируется. На первом эфире сверяйте GSI с задержкой захвата игры.

OBS WebSocket необязателен. Если нужно управление сценами: включите WebSocket Server в OBS, укажите URL и пароль в «Настройки → Подключения», нажмите «Подключить OBS». Затем доступны сцены и видимость их элементов. Серверный клиент реализует авторизацию v5, подтверждение запросов и reconnect.

## Команды, матчи и турниры

- «Команды»: название, тег, логотип и строки `SteamID64 никнейм`. Сохранённый SteamID надёжнее привязки по текущей стороне. Автоматическая смена сторон сохраняет постоянный teamId.
- «Матч»: BO1/2/3/5, карта и порядок карт, счёт серии, ручной игровой счёт, оставшиеся паузы и подтверждённый loss bonus. Пустое поле означает «неизвестно». Ручной игровой счёт имеет приоритет до снятия флажка.
- «Турнир»: название, сокращение, дата, описание, формат, логотип и Hub ID.
- Библиотека хранит несколько команд, турниров и матчей. Матч сохраняется вместе с обеими командами и турниром. «Загрузить» заполняет черновик; «Сохранить изменения» делает его активным.
- При переключении ID матча, карты или идентификаторов команд live-снимок очищается. Не переносите игровые данные предыдущего матча в новый вручную.
- «Оформление HUD»: видимость блоков, масштаб, прозрачность, анимации и цвета сторон. Радар имеет отдельные координаты, размер и прозрачность. Произвольное перетаскивание всех блоков пока не реализовано.

Изображения: PNG, WebP или простой SVG до 2 МБ, максимум 4096 × 4096. Файл декодируется и сохраняется локально как PNG. SVG допускает геометрию, текст, локальные градиенты и маски; скрипты, внешние ресурсы, `foreignObject`, `use` и произвольные CSS запрещены. Сложный SVG предварительно экспортируйте в PNG.

## Радар и Nuke

Карты уже входят в проект: **Nuke (два этажа), Mirage, Dust2, Inferno, Ancient, Anubis, Overpass, Train и Vertigo**. HUD выбирает нужную по `map.name` из CS2. Интернет во время матча не нужен.

1. Перезапустите сервер через `START.bat` и обновите источник браузера в OBS.
2. В панели «Эфир» выберите **Матч**. На Nuke радар автоматически появится с игроками, если GSI передаёт позиции наблюдателя.
3. В **Настройки → Радар и карты** можно просмотреть изображения и выбрать этаж: «По наблюдаемому игроку» или «Все этажи рядом». Для обычного запуска загружать PNG и вводить координаты не нужно.

Ручная настройка закрыта в дополнительном блоке. Уже настроенные пользовательские карты сохраняются; первоначальная пустая Nuke заменяется готовой. Если старая ручная настройка мешает, нажмите «Восстановить готовую карту», затем «Сохранить изменения».

Простая инструкция и поправка смещения: [docs/radar-setup.md](docs/radar-setup.md). Изображения и overview-параметры взяты из [зеркала ресурсов CS2](https://github.com/MurkyYT/cs2-map-icons); исходные файлы, версия и контрольные суммы лежат в `assets/maps`. Nuke использует X = −3453, Y = 2887, scale = 7, границу этажей Z = −495. После изменения карты Valve параметры могут потребовать сверки в игре.

## FACEIT

В «Настройки → Подключения» введите серверный Data API Key, Hub ID и/или Match ID. Ключ хранится только на backend, а форма после сохранения очищается. Сохранение пустого поля сохраняет предыдущий ключ. Ошибка FACEIT не мешает ручному эфиру.

«Синхронизировать» и автоматическое обновление обновляют кеш. «Импортировать выбранный матч» явно применяет составы и метаданные. При новом FACEIT Match ID создаётся новый контекст матча, сбрасываются ручной игровой счёт и счёт серии; при наличии списка карт выбирается первая. Текущие HP, деньги и координаты остаются ответственностью GSI. Изменение состава в FACEIT не перезаписывает оформление без явного импорта.

Список хаба ограничен первой страницей (до 100 ongoing-матчей). Для больших хабов используйте точный Match ID. Детали, источники и API: [docs/integrations.md](docs/integrations.md).

## Карточки и анимация

K/D видны всегда, ассисты убраны. HP закреплено сверху; белый след урона задерживается на 420 мс, затем плавно сужается. C4 и набор разминирования вынесены в верхний внешний угол карточки, раундовые убийства — в нижний. Белая часть силуэта оружия показывает остаток магазина, серая — израсходованную долю; при отсутствии `ammo_clip_max` силуэт остаётся белым.

После смерти выводится **урон за текущий раунд** (`round_totaldmg`), не средний ADR. Если источник не прислал поле, отображается `—`. Во время закупки над составами выезжают два блока экономики со стоимостью снаряжения, loss bonus, деньгами и гранатами. Радар уменьшается, наблюдаемый игрок остаётся виден. Размеры карточек не меняются.

На паузе увеличена история без заголовка и диапазона чисел; цвет победы соответствует стороне команды в том раунде. Для `timeout_t/timeout_ct` или ручного выбора показывается команда тактической паузы. Общий `paused` не сообщает команду — HUD её не угадывает.

## Время и достоверность

Backend опирается на `performance.now()` с временным якорем; клиент интерполирует переданный остаток по собственным монотонным часам. Погрешность включает задержку GSI, HTTP и рендеринга; точность игрового тика не заявляется. Небольшой джиттер до 250 мс сглаживается, большие расхождения корректируются сразу.

Бомба и разминирование имеют независимые таймеры. При отсутствии countdown резерв по настройкам запускается только на **наблюдаемом переходе** установки/начала разминирования; источник `estimate` отмечен символом ≈ в HUD. При подключении посреди события неизвестное время не угадывается. Ноль таймера сам по себе не создаёт событие взрыва. Отмена разминирования снимает его шкалу.

При потере GSI игровые таймеры замирают, появляется сообщение. При разрыве WebSocket клиент тоже останавливает игровые отсчёты и переподключается с задержкой до 10 секунд. Ручной таймер паузы подписан и не зависит от присутствия CS2. На ручной паузе составы, экономика и раунд фиксируются единым снимком до Resume.

## Ограничения первой версии

- HUD использовался в первом live-матче; каждое обновление всё равно требует репетиции с вашим наблюдателем и OBS. Исчерпывающий актуальный CS2-контракт Valve публично подтвердить не удалось; [матрица данных](docs/gsi-support.md) отделяет известные поля от гарантий.
- Готовые overview и параметры включены. Их соответствие вашей версии CS2, особенно переходы этажей Nuke, нужно сверить в игре. Условные эмблемы и демонстрационные составы не являются данными FACEIT.
- Kill feed, MVP, прогноз следующей экономики, точная геометрия дыма/огня и прогноз траекторий не включены. Гранаты показываются условными маркерами только по полученным данным.
- История раундов накапливается из подтверждённых событий. При позднем подключении после смены сторон неизвестные прошлые победители не угадываются.
- Demo — синтетические сценарии, не парсер `.dem`. В нём есть игровой раунд, закупка, разминка, бомба/defuse, победа, паузы, смена сторон, овертайм и потеря подключения.
- API ключи хранятся локально в SQLite, без шифрования Windows DPAPI. Не передавайте каталог `data` другим людям. Сервер доступен только на loopback; удалённая многопользовательская работа не предусмотрена.

## Troubleshooting

**Нет пакетов:** проверьте расположение cfg, перезапуск CS2, порт, токен, LIVE и разрешённый spectator-режим. GSI получает 401 при неправильном токене. 202 означает старый пакет или включённый Demo.

**Не видно 10 игроков / радара:** это не исправляется подстановкой демоданных. Сверьте подписки `allplayers_*`, фактические capabilities в диагностике и доступ наблюдателя. Для встроенных карт изображения и параметры уже заданы. Проверьте XYZ в «Настройки → Радар и карты → Сейчас в игре → Координаты игроков для проверки».

**Панель просит ключ:** это старая сборка или старый процесс сервера. Перезапустите HUD и обновите страницу. В текущей версии входа, выхода и операторского ключа нет.

**Изменения формы не применились:** нажмите «Сохранить изменения». Ошибка указывает первое поле валидации. SteamID должен содержать цифры; команды должны иметь разные ID и противоположные стороны.

**OBS пустой:** проверьте `/preview`, размер Browser Source, LIVE/Demo, видимость production и активную сцену. Сначала проверьте источник в обычном браузере.

**Порт занят:** закройте предыдущий процесс HUD или запустите `$env:PORT='3192'; pnpm start`. Измените URL Browser Source и заново скачайте cfg. Для dev-режима также обновите proxy в `vite.config.ts`.

**Нет npm/pnpm:** используйте готовый ZIP или START_OVERLAY.bat из исходников: установка инструментов автоматическая. При ошибке смотрите `data/setup.log`.

**Перед переносом/резервной копией:** остановите сервер и скопируйте `data` целиком, включая SQLite WAL при его наличии. Для копии без личных данных исключите `data`, `artifacts`, `.pnpm-store`, `node_modules` и установите зависимости заново.

Актуальные изменения радара, Nuke, Cache и требования к материалам: [radar-feedback.md](docs/radar-feedback.md).
