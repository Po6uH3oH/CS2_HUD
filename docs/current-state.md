Актуально на 13 ноября 2026. Этот файл описывает текущий результат; `work-progress.md` хранит историю, включая уже отменённые варианты.

## Проект и запуск

- Репозиторий: https://github.com/Po6uH3oH/CS2_HUD, основная ветка `main`. Локальная копия пользователя: `E:\CS2_HUD`.
- Версия 0.2.0: готовый Windows x64 ZIP включает Node.js, Electron, compiled backend и зависимости. Запуск `CS2 HUD.exe`, браузерный режим `START_OBS.bat`. Для исходников START_OVERLAY.bat / START.bat автоматически готовят локальный Node.js и pnpm, проверяют/восстанавливают зависимости и актуальность frontend. Системные инструменты/Codex не требуются.
- Backend по умолчанию 127.0.0.1:3190; `/admin`, `/overlay/game`, `/overlay/pause`, `/preview`. HUD прозрачный; фон только в админке. Операторской авторизации нет, но GSI-токен остаётся.
- Окна Electron имеют постоянные разные заголовки: `CS2 HUD Overlay` и `CS2 HUD — Панель управления`. Обработчик `page-title-updated` запрещает общей HTML-странице заменять их. Для OBS Window Capture выбирайте HUD и строгое совпадение заголовка; требуется перезапуск Electron. Проверены синтаксис desktop, TypeScript, 81 тест и сборка; захват в живом OBS после этой правки не проверялся.
- Рабочая SQLite и секреты исходников находятся в `data/`, готового приложения — `%LOCALAPPDATA%\CS2HUD`, не в Git. 10 экспортированных команд и их логотипы — `assets/library/`; импортируются однократно при новой установке.

## Запуск на новом ПК и готовый релиз (13 ноября)

- `scripts/package-windows.mjs`: ручная упаковка Electron в `resources/app`, отдельный node.exe, production deps, все assets и экспортированная библиотека; явный список исключает рабочие data/секреты. - `.github/workflows/windows.yml`: сборка/проверки на Windows при main/tag/manual; GitHub Release для тега создаётся только после успешной сборки (уже существующий не перезаписывается). ## Первый live-матч: команды и loss-бонус (11 ноября)

- Исправлено отсутствие loss-бонуса: теперь используется GSI `consecutive_round_losses`, стандартная формула 1400 + 500 × min(4, counter). Ручное значение имеет приоритет, отсутствие поля остаётся неизвестным. Пользовательские серверные выплаты GSI не сообщает.
- `match.autoSides` по умолчанию true, старые настройки получают поле через schema default. Сначала определяется пара сторон по известным SteamID/roster (достаточно одного непротиворечивого совпадения), затем ВСЕ игроки стороны распределяются в соответствующую команду, включая замены. Конфликт якорей даёт предупреждение и сохраняет предыдущую раскладку. Без совпадений используются запомненные игроки текущей карты, затем стартовые стороны карты/команд.
- В «Матч» и «Команды» общий блок с никнеймами обеих сторон, переключателем автоматики и кнопкой привязки текущих игроков. Привязка заменяет оба roster/steamIds и включает авто; применяется кнопкой «Сохранить изменения», остаётся после перезапуска, переносится в библиотеку отдельно. Нужны свежие LIVE-данные и хотя бы один игрок с каждой стороны. Ручная пауза может удерживать старый снимок: перед привязкой снять её.
- «Поменять стороны» / «Сменить сторону» включают ручной режим. В нём реальные GSI-стороны игроков не подменяются: меняется сопоставление команда ↔ сторона. Сохранение переобрабатывает кеш GSI немедленно, без нового heartbeat/перезапуска; корректирует также ручную паузу, историю и принадлежность гранат. Исходные настройки карты и SteamID не отменяют ручной выбор.
- Инструкция: `docs/team-assignment.md`. Проверено: TypeScript, 89 тестов, production build; браузерная привязка, сохранение, автообмен сторон, loss-бонус на закупке/паузе при 2560×1440. Только синтетические данные, отдельный порт 3198 и DATA_DIR `artifacts/team-assignment-check/data`; рабочая БД/матч не изменялись. Снимки `admin.jpg`, `game.jpg`, `pause.jpg` в той же папке проверки.

## Текущие визуальные решения

- Компактные зеркальные карточки в три строки внизу по краям. Полоса номера наблюдателя с внешнего края, HP — тёмная заливка; ещё более тёмный след урона. Белые звёзды убийств за раунд, K/D без ассистов, четыре слота гранат, C4/киты рядом с бронёй. После смерти карточка сужается и показывает DPR.
- Приоритет основной иконки: винтовка/основное > пистолет > Zeus > нож. Неактивное оружие серое. Пользовательские SVG и GIF находятся в `assets/icons`.
- T слева, CT справа; стабильные ID команд сохраняют счёт/пики при смене сторон.
- Порядок карт — **одна широкая полоска над радаром**, а не список под ним. Логотип пика, название, счёт прошлой карты, стрелка. Текущая карта белая, остальные серые; результат своего пика зелёный при победе и красный при поражении. Нет BOx/DECIDER/LIVE в полоске. BO3 подгоняется по ширине, BO5 при переполнении плавно ходит влево-вправо. Расширяется только шапка, не изображение радара. X vs Y справа от шапки, верхний край на уровне счёта.
- showMapOrder и showAliveCount — отдельные переключатели в оформлении. Пики задаются вручную, FACEIT пока даёт только порядок. Итоги карт сохраняются из GSI gameover; ручные итоги не пересчитывают общий счёт серии. См. `hud-series.md`.
- Ослепление показывается **только на радаре**. Побеление карточек отменено пользователем. Live-лог Ancient показал `flashed` только 0/1; поддерживается и диапазон 0–255. Автоопределение неоднозначно для одиночной единицы, точную силу из двоичного сигнала восстановить нельзя.
- На Nuke убраны подписи «Верхний» и «Нижний» поверх изображений этажей; сами этажи и настройки выбора сохранены.
- Цвет смока берётся только из стороны, сохранённой при броске, и не меняется после смерти владельца. Убрана чёрная обводка: остаётся одна цветная линия толщиной 3. Начало затухания сдвинуто на 1.5 секунды: теперь дым затухает от 19 до 20 секунды **после раскрытия** (`effectTime`), затем скрывается, даже если GSI ещё держит сущность. Дополнительного затухания после удаления нет.
- Летящие гранаты без кругов; HE и flash имеют конечные эффекты, огонь использует `fire.gif` по точкам flames. C4 — `map_bomb.svg`, пульсация установлена синхронно с иконкой счёта; `ui/explosion.gif` на счёте при взрыве.
