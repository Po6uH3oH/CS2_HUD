# Архитектура и поток данных

```text
CS2 spectator → POST /api/gsi → token + size validation
  → GsiNormalizer → единый GameState → read-only WebSocket → React Overlay
DemoEngine ────────────────────────↑                         ├─ OBS routes
                                                          ├─ Preview
                                                          └─ Electron window
Operator → local REST → Settings / manual commands → SQLite + state projection
FACEIT → server-only REST/cache → explicit metadata import
OBS ← authenticated v5 RPC ← operator REST
```

## Разделение ответственности

`packages/shared/types.ts` — wire-контракт и нормализованные модели. React не читает необработанный GSI. `packages/core/index.ts` содержит чистые преобразования координат, экономику, таймеры и stateful GSI-normalizer. `demo.ts` создаёт тот же `GameState`, явно с `mode=demo`; его данные не проходят за real GSI и никогда не сливаются с Live. HTTP, SQLite, GSI token и интеграции изолированы в backend.

Один React bundle содержит `/admin`, `/preview` и три overlay routes. Это сознательно компактная структура первой версии вместо независимых frontend-проектов с дублированием модели. `Overlay` — общий компонент со stage 2560×1440 и ResizeObserver. Предпросмотр не является упрощённой копией и не нужен backend для кадров рендеринга; backend отправляет только состояние.

## Состояние

Settings хранят постоянные ID команд, их оформление, известные SteamID, метаданные активного матча/турнира, параметры радара и отображения. GameState хранит только наблюдённое состояние текущего контекста и источники таймеров. Счёт и статистика могут быть null. Состояния соединения GSI и WebSocket различаются.

GSI сохраняет отсутствующие скалярные поля между пакетами. Присутствующая коллекция `allplayers`, `weapons`, `grenades` считается новым составом коллекции; для сохранившихся игроков и гранат вложенные скаляры объединяются. `null`, `removed` и явно исчезнувшие поля из `previously` удаляют старое значение. Это политика адаптера полных spectator-коллекций; для другого upstream с отдельными player-delta потребуется явный адаптер к этому контракту.

При смене карты, provider, match ID, откате round или новом warmup контекст сбрасывается. При смене раунда очищаются раундовые данные и устаревшая экономика; K/A/D текущего матча остаются. Стороны команд определяются по постоянному составу, затем последней известной принадлежности, затем операторской привязке стороны. При полноценной смене сторон счёт берётся из соответствующего блока `map.team_ct/team_t`.

## Приоритеты

1. GSI — оперативное состояние игры, при наличии данных.
2. Ручной scoreOverride — явная коррекция до отключения; ручная пауза имеет свой источник и фиксированный снимок.
3. FACEIT — кеш метаданных и явный импорт. Автосинхронизация не перезаписывает ручное оформление.
4. Demo — полностью отдельный выбранный режим.

При новом FACEIT Match ID сбрасывается старый live-контекст и ручная коррекция счёта. Старый match bundle можно сохранить в библиотеку перед импортом. Неподтверждённые API-данные не подменяются расчётами; допускается только отдельно обозначенный timer estimate после наблюдённого перехода.

## Время

Модель Timer: remaining, duration, updatedAt, running, source. Сервер вычисляет elapsed по performance.now() относительно якоря; broadcastAt позволяет клиенту начать интерполяцию с времени отправки, даже при открытии нового Browser Source между GSI-пакетами. На клиенте также используется performance.now(), а interval только инициирует перерисовку.

GSI phase countdown и bomb countdown обрабатываются по фазе. Defuse countdown не заменяет ранее установленный deadline взрыва. Малый джиттер сглаживается; при окончании раунда и gameover таймеры очищаются. Сетевые задержки не могут быть устранены без игрового timestamp; tick-perfect синхронизация не заявляется.

## Надёжность

Loopback bind и проверка Host/Origin, отдельный случайный GSI-токен, ограничение размера тела, zod-валидация, безопасная обработка файлов, ограниченный журнал, write-only секреты. WS только для чтения, с полными снимками, reconnect и ограничением буфера клиента. Backend graceful shutdown закрывает сокеты, SQLite и таймеры.

SQLite WAL сохраняет настройки/сущности/журнал, но никогда не восстанавливает старую телеметрию как live. При потере GSI счётчики замораживаются до свежего пакета. FACEIT использует TTL-кеш, request deduplication и Retry-After/backoff; недоступность интеграций не блокирует ручное управление.

## Расширение

Серверные события можно добавить отдельным авторизованным адаптером в нормализованную модель, если организатор реально предоставляет такой интерфейс. Новые карты добавляются JSON-конфигурациями и overview-слоями. Новые оверлеи используют существующий WireSnapshot. Для чтения `.dem`, удалённых операторов и полного реестра турнирных сеток нужны отдельные модули. Нативное окно находится в `apps/desktop`: прозрачный Electron BrowserWindow с отключённым фокусом и пропуском мыши, без Node API в renderer. Оно переиспользует локальный сервер или запускает собственный; при выходе закрывает только собственный процесс. См. [запуск](desktop-overlay.md).

Панель локальная и открывается без авторизации; логин, logout, cookie-сессии и операторский токен удалены. GSI-токен, ключ FACEIT и пароль OBS имеют отдельное назначение и сохранены. Пакеты GSI публикуются сразу, tick демо — 50 мс. Сглаживание маркеров выполняется CSS-переходом 200 мс; большие скачки, смена раунда/карты/слоя сбрасывают интерполяцию.

Актуальные изменения радара, Nuke, Cache и требования к материалам: [radar-feedback.md](radar-feedback.md).
